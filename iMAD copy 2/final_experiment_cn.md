## 1. 实验目标（Experimental Objective）

本项目的主要贡献是 **MMAD-ToM**——一个面向 LLM 推理的多智能体辩论框架。此前投稿的审稿人要求除了普通单智能体对照之外，再补充一个有竞争力的、较新的多智能体辩论（MAD）基线做对比。为此选择 **iMAD**（Fan, Yoon, Ji——*iMAD: Intelligent Multi-Agent Debate for Efficient and Accurate LLM Inference*，arXiv:2511.11306）作为 **Baseline 2**，原因是它是一个较新的、带选择性触发机制的 MAD 方法，且其分类器/损失函数部分有公开参考实现，使得忠实复现具备可行性，同时它与 MMAD-ToM 在设计上确实不同（iMAD 是"自我批判 + 门控触发的选择性辩论"，MMAD-ToM 则是本项目自身的机制）。

**与其他基线的关系**：
- **Baseline 1 = Single-Agent（单智能体）**：针对每个数据集设计的纯提示词基线，来自一次单独完成、已交付的评测（`Single-AgentV2/`），本报告不重新运行。
- **Baseline 2 = iMAD**（本报告）：自我批判 → 分类器门控 → 选择性多智能体辩论。
- **MMAD-ToM**：本项目自有方法，另行评测，不在本报告范围内。

**明确的范围声明（贯穿本系列所有实验，此处重申）**：iMAD 与 MMAD-ToM **不共享相同的内部架构**。本报告不声称两者在结构上等价——iMAD 在此被重建并作为一个独立的竞争基线来评估，而非作为 MMAD-ToM 的组成部分或消融实验。

**本次实验拟回答的问题**：
1. 对于中小规模开源权重模型（7B/mini 级别），一个忠实重建的 iMAD 流程在多种推理任务类型（算术应用题、常识选择题、代码理解自由文本、研究生级选择题）上，相对纯单智能体基线是否能带来准确率提升？
2. 若观察到收益或损失，其在流程中的具体来源是自我批判阶段还是选择性辩论阶段？
3. 论文原设计中"在 PubMedQA 上训练、跨数据集/跨模型零样本复用"的分类器门控，是否具有有意义的选择性，还是会在跨领域/跨模型迁移时退化？
4. 上述发现是否取决于模型能力、任务类型，或两者兼有？

## 2. iMAD 方法复现说明（iMAD Method Reconstruction）

### 2.1 从输入到最终答案的完整流程

```
问题（若为选择题则含选项）
   │
   ▼
① 自我批判单智能体阶段（同一个 LLM，内部三步，一次 API 调用完成）
   步骤1 — 初始思维链推理 → initial_answer + initial_confidence
   步骤2 — 强制反驳（必须执行，非可选）→ alternative_answer + alternative_confidence
   步骤3 — 重新权衡 → final_answer + final_confidence（即 Acc(0) / "辩论前答案"）
   │
   ▼
② 41维可解释特征抽取
   来自问题文本、步骤1推理、步骤2/3自我批判文本：
   表层统计量、问题类型词汇线索、句法深度、可读性指标、
   词性计数、犹豫/确信/转折词汇线索、置信度分数
   │
   ▼
③ FocusCal 分类器打分（MLP2Head，按学生模型分别训练，训练集为 PubMedQA；
   评测数据集本身从不用于分类器训练）
   │
   ▼
④ 选择性门控：classifier_score < τ（0.7）？
   ├─ 否 → 跳过辩论，保留步骤3的自我批判答案作为最终答案
   └─ 是 → 触发多智能体辩论
            │
            ▼
   ⑤ Debater(Affirmative) ⇄ Debater(Negative) ⇄（内部）Judge，最多5轮
      - Affirmative 每轮开场，为当前答案辩护
      - Negative 提出批评，可提出不同答案，必须给出 agree: true/false
      - Judge 对该轮作出评估：preference="Yes"（一方已完全说服另一方 /
        辩论应结束）立即以该轮答案终止辩论
      - preference="No" 则进入下一轮
      - 若5轮结束仍无"Yes"：由单独的 Finalization 调用综合完整对话记录
        及累积的候选答案集合（"options2"）生成系统最终答案
   │
   ▼
⑥ 最终答案 + 全流程 token/轮次统计
```

**同一个学生模型承担所有角色**——自我批判、Affirmative、Negative、内部 Judge——仅通过系统提示词区分，与论文本身"单一模型扮演所有角色"的设计一致（并非异构多模型辩论）。

### 2.3 状态机、重试与终局裁决（真实代码行为）

- **JSON schema 重试**：每次辩论角色调用（Affirmative、Negative、逐轮 Judge、终局 Judge）在 schema 校验失败时最多重试 **3 次**（`MAX_JSON_RETRIES = 3`），超过后记为一条 `debate_errors` 记录，并对该角色沿用上一轮的答案作为兜底。
- **传输层重试**：与上述独立，每次 HTTP 调用在遇到 408/429/5xx 响应时最多重试 **3 次**（默认 `--retries 3`）后才抛出异常。
- **答案字段校验**（选择题用 `normalize_letter`，CS1QA 用 `_clean_answer`）：去除空白/标点，并检查其值属于有效标签集合（选择题）或非空（CS1QA）。
- **parser 恢复兜底**（仅 Phi，见第11节）：若结构化 `answer` 字段缺失/无效，但自由文本 `argument` 字段中恰好包含**唯一且无歧义**的选项字母标记（选择题）或唯一明确的 `(answer: ...)` 标记（CS1QA），则恢复该值作为答案——**绝不**默认采用 Affirmative 的答案，**绝不**在出现多个候选时进行猜测。
- **提前终止**：任意一轮中 Judge 给出 `preference: "Yes"`，辩论立即以该轮的 `judge_answer` 结束。
- **终局裁决**：若没有任何一轮终止辩论，第5轮之后会有一次单独的 Finalization 调用，综合完整对话记录及累积的 `options2` 候选集给出最终答案。若该 Finalization 调用本身也未通过 schema 校验，则沿用第5轮（或最后可用）的 Judge 答案，终止原因记为 `finalization_failed_carried_forward`——**流水线从不会让某个样本的最终答案为空**（由 `every_example_has_a_final_answer_or_is_counted_incorrect` 这一 sanity check 验证，在全部12个组合中均以0违规通过）。

### 3.1 断点续跑与逐样本落盘

每个阶段在每个样本处理完成后立即写入一个独立的 JSON 文件（`self_critique/records/{index:06d}.json`、`per_example_records/{index:06d}.json`、`debate_transcripts/{question_id}.json`），且每个执行脚本在处理某个索引前都会先检查是否已存在对应的输出文件。这意味着：
- 一个被中断/超时的任务（确实发生过一次，即 Mistral 的 MMLU-Pro 运行——SLURM 4小时墙钟超时，此时已保存 8470/12032 条自我批判记录）能够从下一个未处理的索引干净地恢复，不会重复处理，也不会产生重复工作，这一点由 `exact_n_examples_evaluated` sanity check 验证。
- 并发执行（`--concurrency N` / `--debate-concurrency N`，通常为10–16）通过线程池并行化互相独立样本的 API 调用；已在一个100样本的诊断性运行上验证过，其触发计数和 sanity check 结果与顺序执行完全一致，仅存在 temperature=0.3 带来的预期采样方差（体现在具体 token 级输出上）。
- 从集群到本地 Mac 的结果同步就是对已完成结果目录的一次普通 `rsync -avz`（不做任何"部分状态"假设）；在同步完成之前，集群端副本始终是权威版本。

### 3.2 失败重试 vs. schema 重试（两个独立层次）

1. **传输层**（`ChatClient.complete()`）：对 HTTP 请求本身（网络错误、5xx、429）最多重试3次后才抛出异常。
2. **schema 层**（各辩论引擎内部的 `_call_with_retry()`）：若模型的 JSON 输出未通过校验（字段缺失、标签无效、在 `max_tokens` 处被截断），会对**同一个**辩论角色调用最多重试3次，与该次 HTTP 调用本身是否成功无关。

两层重试每次都会发起一次全新的采样调用（而非缓存/重放响应），因此 schema 层的重试可能产生与前一次真正不同的模型输出。

## 6. 指标定义（Metrics）

除特别标注外，所有指标定义在各组合间完全一致。N 为该组合的样本总数（是下表除特别说明外每个比率的分母）。

| 指标 | 公式 | 定义 |
|---|---|---|
| **Single-Agent Accuracy（单智能体准确率，SA）** | correct / N | 复用的、单独运行的纯基线的准确率（见第5.5节）。 |
| **Acc(0) / Self-Critique Accuracy（自我批判准确率）** | correct(辩论前答案) / N | 自我批判阶段自身步骤3最终答案的准确率，在任何辩论**之前**——即论文中所称的"辩论前答案"，对全部未触发（未进入辩论）的样本原样采用。 |
| **Final iMAD Accuracy（最终 iMAD 准确率）** | correct(final_answer) / N | 完整流水线运行后的准确率（触发的样本经辩论，未触发的样本保留 Acc(0)）。 |
| **Self-Critique Delta（自我批判增量）** | Acc(0) − SA | 相对于一次性纯答案，仅由自我批判阶段带来的变化。 |
| **Debate Delta（辩论增量）** | FinalAcc − Acc(0) | 仅由选择性辩论阶段带来的变化。 |
| **Total Delta（总增量）** | FinalAcc − SA | 相对纯基线的端到端变化；按构造等于 自我批判增量 + 辩论增量。 |
| **Trigger Rate（触发率）** | num_triggered / N | classifier_score < τ 的样本占比，即辩论被调用的比例。 |
| **wrong-recall（错误召回率）** | 辩论前答错且被触发的数量 / 辩论前答错总数 | 在自我批判阶段答错的样本中，门控正确送入辩论的比例。理想门控应使该值高。 |
| **false-trigger（误触发率）** | 辩论前答对且被触发的数量 / 辩论前答对总数 | 在自我批判阶段已经答对的样本中，门控仍不必要地送入辩论的比例。理想门控应使该值低。 |
| **correct→incorrect（对→错）** | 计数 | 辩论前答案正确、但最终（辩论后）答案错误的样本数——即有害漂移。 |
| **incorrect→correct（错→对）** | 计数 | 辩论前答案错误、但最终答案正确的样本数——即真正的修复。 |
| **Drift Rate（漂移率，DR）** | correct→incorrect / N | 由辩论导致的有害答案变化在总体中的比例。 |
| **Recovery Rate（恢复率，RR）** | incorrect→correct / N | 由辩论导致的有益答案变化在总体中的比例。按构造，辩论增量 = RR − DR（在每个组合上均作为显式 sanity check 验证，0处违规）。 |
| **SDI（自我批判损害/修复指数，Self-critique Damage/repair Index）** | (repair − damage) / N，其中 damage = (initial_answer 正确 且 辩论前答案错误)，repair = (initial_answer 错误 且 辩论前答案正确) | **本报告自定义的指标**，与此前部分单数据集报告中使用方式并不完全相同——见下方说明。用于衡量自我批判阶段自身内部（步骤1→步骤3）的反思相对于其**自身起点**而言是有益还是有害，与用于计算 Self-Critique Delta 所选用的外部 Single-Agent 基线无关。 |
| **strict-schema validity（严格 schema 有效率）** | schema_valid / N | 自我批判响应第一次尝试即通过严格 JSON schema 校验（所有字段齐全且取值合法）的比例。 |
| **robust recovery rate（鲁棒恢复率）** | recovered / (recovered + still-unresolved) | 仅在代码中存在"仅 Phi 使用"的 parser 恢复机制（见第2.2节、第11节）时才有定义——**对 Qwen2.5 和 Mistral 为 N/A**，因为其运行早于该机制存在。 |
| **unresolved failure rate（无法恢复的失败率）** | 真正无法恢复的数量 / N | 对选择题/CS1QA：取自 `self_critique/summary.json` 的 `extraction_method_counts` 中的 `no_answer_found` 计数。对 GSM8K：直接检查 `pipeline_records.json` 中 `NO_ANSWER_FAILURE` 哨兵实际出现的次数（**在全部3个 GSM8K 模型上均为0次**，即回退式数值抽取吸收了全部 schema 失败，从未触发该哨兵）。 |

### 6.1 全部12个组合的一致性检查结果

1. **本报告主表中，全部12行的 SA/自我批判/总增量均以统一的、同一个官方基线（见第5节）计算**，唯一例外是 Qwen2.5 自身原始的 GSM8K 报告曾以*另一个*基线（匹配纯CoT对照，76.50%）作为这些增量指标的头条数字。**两种基准均在第7节并列给出**，明确标注，以避免读者混淆二者，或在跨模型比较时误用了不匹配的基准相减。
2. **SDI 在全部3个 CS1QA 组合中均无法计算。** CS1QA 的正确性是针对实际生成并缓存下来的"辩论前答案"和"最终答案"事后由裁判判定的；自我批判阶段自身中间产生的 `initial_answer` 文本从未被送去给外部裁判评判。要为 CS1QA 计算 SDI，需要对此前从未被评判过的文本发起新的裁判调用——这属于新的推理调用，本报告被明确要求不得执行。**因此全部3个 CS1QA 行的 SDI = N/A**，而非0，也不是被省略。
3. **"鲁棒恢复率"仅对 Phi-4-mini-instruct 的 CommonsenseQA、CS1QA、MMLU-Pro 三次运行有意义。** 底层 parser 恢复代码（`recover_letter_from_argument` / `recover_answer_from_argument`）在 Qwen2.5 与 Mistral 的运行执行时尚不存在——已直接检查其 `pipeline_records.json` 文件确认 `recovered_answers` 字段**不存在（0个事件）**，而非"存在但从未触发"。若将 Qwen2.5/Mistral 的该指标报告为"0%"会误导读者以为该机制当时存在只是恰好从未起效；因此这些项标记为 N/A，并给出上述确切说明。
4. **MMLU-Pro 按类别的准确率对 Qwen2.5 或 Mistral 已交付结果中原本并不存在**（其源数据集文件无类别字段）。本报告通过对已计算完成的最终答案做事后 join 来填补这一缺口（见第5.4节），这是聚合而非重新运行，在其出现的每处均已披露（见第9节）。
5. **未发现其他数值矛盾**——将任何单数据集 `experiment_summary.md`、其自身的 `config.json`/`evaluation_metrics.json`，与本报告从原始 JSON 独立重新计算的结果相比较，均未发现矛盾。此前少数几份报告的四舍五入文字表述（例如 Qwen2.5 CS1QA 的 Debate Delta 印刷为 "−0.44%"）与本报告新计算得到的全精度值（−0.43%）之间存在不超过0.02个百分点的差异——这些均为纯粹的中间四舍五入产物，已通过用同一批 `overall_dr`/`overall_rr`/转移计数重新计算加以验证，不视为冲突。

## 8. 分模型分析（Per-Model Analysis）

### 8.1 Qwen2.5-7B-Instruct

在四个数据集中的三个上（CommonsenseQA −1.80%、CS1QA −1.30%、MMLU-Pro −2.88%），Qwen2.5 的总增量绝对值是三个模型中最小的；而在 GSM8K 上则是三者中最大的（相对官方基线为 −23.96%；相对其自身匹配对照为 −13.65%）。在每个数据集上，损失都集中在**自我批判阶段**：Self-Critique Delta 在全部4个数据集上均为负（相对官方基线分别为 −28.43%/−1.55%/−0.86%/−3.28%），而 Debate Delta 在 GSM8K（+4.47%）和 MMLU-Pro（+0.40%）上小幅为正，在 CommonsenseQA（−0.25%）和 CS1QA（−0.43%）上基本持平或略负。门控在 GSM8K 上表现出真实但有限的选择性（错误召回率30.05% vs. 误触发率12.08%，差距17.97个百分点，有利于正确分流），在 MMLU-Pro 上同样如此（42.50% vs. 36.61%，差距5.89个百分点），但**在 CommonsenseQA 上退化为统计噪声**（64.29% vs. 65.72%——该模型在此数据集上的门控与随机无异）**在 CS1QA 上同样如此**（75.41% vs. 75.43%——同样无法区分；见第10.5节关于门控退化的讨论）。Qwen2.5 在每个数据集上的自我批判 schema 有效率都是三个模型中最高的（GSM8K 99.1%，CommonsenseQA 97.87%，CS1QA 99.35%，MMLU-Pro 96.10%）——它比另外两个模型都更可靠地遵循所要求的 JSON 输出格式，因此其准确率损失几乎不受解析失败驱动，而是一种真实的推理/自我批判行为效应，而非格式问题。

### 8.2 Mistral-7B-Instruct-v0.3

在不涉及分类器最极端失配情形的数据集上，Mistral 的总增量表现最为**一致、温和**：−14.94%（GSM8K）、−3.61%（CommonsenseQA）、−4.06%（CS1QA）、−2.93%（MMLU-Pro）——没有哪个数据集像 Phi 在 CS1QA 上、或 Qwen 在 GSM8K 上那样产生极端异常值。自我批判在各处都是主要损失来源（−19.18%/−3.93%/−4.00%/−3.07%），而 Debate Delta 幅度虽小但符号随数据集而变：在 GSM8K（+4.25%）、CommonsenseQA（+0.33%）、MMLU-Pro（+0.14%）上为正，在 CS1QA（−0.05%）上基本为零略偏负。Mistral 在 GSM8K 上的自我批判 schema 有效率是三个模型中**迄今最低的（65.3%）**——它比 Qwen2.5 或 Phi-4-mini 都更频繁地用自然语言含糊其辞（例如"一个小于26但无法精确确定的数字"），而不是给出一个明确数字。尽管如此，"永不排除样本"的回退抽取策略吸收了这些失败中的每一个（GSM8K 上0例无法恢复）。Mistral 的门控在 GSM8K 上是**触发最激进的**（47.69%，大约是 Qwen2.5 的19.56%的两倍），在 MMLU-Pro 上同样也是三者中最高的（63.85%），与其分类器产出更多低置信度分数相一致；但在 CS1QA 上，其门控却是三者中**最不激进**的（34.38%，对比 Qwen 的75.42%和 Phi 的97.94%）——见第10.5节，这是本报告中"分类器存在与领域/模型相关而非固定不变的模型专属'性格'"的最清晰证据。

### 8.3 Phi-4-mini-instruct

在四个数据集中的三个上（GSM8K −34.42%、CS1QA −7.20%、MMLU-Pro −7.11%；仅 CommonsenseQA 并非其最差项，为 −4.58%，接近 Mistral 的 −3.93%），Phi-4-mini 表现出三个模型中**最大的自我批判阶段损失**，但同时也表现出在 GSM8K（+6.67%，本表中最大的单一 Debate Delta）和 CommonsenseQA（+2.05%）上**最大的辩论阶段恢复**。尽管如此，其净总增量在 GSM8K 上仍是三者中最差的（−27.75%），而在 **CS1QA 上更为显著（−9.10%，是整张12行表中单个最差的一格）**，这是由 CS1QA 高达97.94%的近乎全触发率所驱动（见第9.3节、第10.5节）——对于这一模型/数据集组合而言，辩论已更接近"全程开启的 MAD"而非"选择性 MAD"，且辩论本身在此处也是净有害的（Debate Delta −1.89%），而不是 Phi 在其他触发场景中通常表现出的小幅净正效应。Phi 的自我批判 schema 有效率处于中等水平（GSM8K 76.8%，CommonsenseQA原始运行83.95%/MMLU-Pro 82.48%，CS1QA 92.74%）——其解析失败率是真实存在的，但"永不排除样本"的策略以及（针对 CommonsenseQA/CS1QA/MMLU-Pro）额外的 parser 恢复修复（见第11节）吸收了其中绝大多数，未造成信息损失。

### 10.2 收益是否集中在少数样本上？

是的，且在各组合间一致。✗→✓（修复）与 ✓→✗（有害）合计在任何组合中都从未超过约 N 的10%（占比最大的是 Phi/CS1QA 的 (88+53)/1847 = 7.63%，以及 Phi/MMLU-Pro 的 (560+649)/12032 = 10.05%）。绝大多数——通常85%–98%——落在两个"稳定"类别（✓→✓ 或 ✗→✗）中，意味着辩论的净效果，无论方向如何，对绝大多数样本而言只是在"本就会得到相同结果"的答案之上施加了一个小扰动。这直接支持**下方结论(3)**：辩论是一种低吞吐量的纠错机制，而非对答案的大范围重新推导。

### 10.3 有害漂移是否超过修复？

| | DR > RR（辩论净有害） | RR > DR（辩论净有益） | DR ≈ RR（净中性，差值<0.1pp） |
|---|---|---|---|
| 数量（共12） | 3 | 8 | 1 |
| 具体组合 | Qwen2.5/CommonsenseQA、Qwen2.5/CS1QA、Phi/CS1QA | Qwen2.5/GSM8K、Mistral/GSM8K、Phi/GSM8K、Mistral/CommonsenseQA、Phi/CommonsenseQA、Qwen2.5/MMLU-Pro、Mistral/MMLU-Pro、Phi/MMLU-Pro | Mistral/CS1QA |

在12个组合中的8个上，辩论是净有益的（RR > DR，即 Debate Delta 为正）——在 GSM8K 和 MMLU-Pro 上最为一致（三个模型均如此）。辩论呈净有害的场合，恰恰是门控选择性已经退化的场合（见第10.5节）：第9节已表明 Qwen2.5 在 CommonsenseQA 和 CS1QA 上的门控在统计意义上与随机无异，而 Phi 在 CS1QA 上的门控则过度触发至接近全量触发——在这三个净有害的场合，辩论并没有被选择性地应用到真正需要它的样本上，因此其"有害 vs. 有益"比例接近于（在 Phi/CS1QA 的情形下甚至超过）一个不加选择、全程开启的辩论所会产生的比例。

### 10.4 "更少辩论" vs. "更安全的辩论"

这是两个不同的概念，本数据能够将二者区分开。**触发率**衡量辩论发生的*多少*；**门控差距**（错误召回率 − 误触发率）衡量辩论的*瞄准精度*。一个模型/数据集组合可能触发率不高但瞄准仍然很差（Qwen2.5/CS1QA：75.42%的触发率并不低，但其门控差距为−0.02pp——尽管在四分之三的样本上触发，瞄准却基本等同随机），也可能触发率很高但相对瞄准得还算合理（Phi/MMLU-Pro：55.39%触发率，+8.94pp差距——按差距大小衡量是本表中校准最好的门控，即便它仍在多数样本上触发）。本报告中表现*最差*的数据集/模型组合（真正最差的是 Phi/CS1QA，总增量 −9.10%）是由**高触发率**与**接近零的瞄准精度****同时**驱动的——"更多、更不安全的辩论"严格劣于单独出现其中任一因素，而这恰恰正是 Phi/CS1QA 所呈现的组合。

### 10.5 门控是否存在跨模型/跨数据集迁移问题？

**是的——这是本报告中数据支持最充分的机制层面发现。** 直接证据来自对全部三个模型在 CS1QA 上的分类器分数分布进行的直接计算（基于原始 `pipeline_records.json`）：

| 模型（CS1QA） | 分类器分数中位数 | 低于 τ=0.7 的比例 | 观测触发率 |
|---|---:|---:|---:|
| Phi-4-mini-instruct | 2.8×10⁻⁷ | 98.32% | 97.94% |
| Qwen2.5-7B-Instruct | 0.165 | 75.42% | 75.42% |
| Mistral-7B-Instruct-v0.3 | 0.998 | 34.49% | 34.38% |

**完全相同**的 τ=0.7 阈值，应用于同一套（尽管每个模型分别训练）在 PubMedQA 上训练的分类器架构，作用于**相同**的 CS1QA 数据集，产生的触发率却仅因生成待打分自我批判文本的模型不同，就从34%跨越到98%。这无法归因于真实的任务难度差异（三个模型面对的是完全相同的1847道 CS1QA 题目）——这反映出分类器的置信度特征分布在不同模型的自我批判写作风格之间发生了截然不同的迁移，使得同一个固定阈值落在每个模型各自分数分布中完全不同的位置。Phi 在 CS1QA 上分类器分数近乎完全坍缩至0（这一领域显然与分类器训练所用的 PubMedQA 医学问答自我批判文本迥然不同）是整个"数据集×模型"网格中此现象最极端的单一实例，并直接解释了该模型在该数据集上近乎全量触发（97.94%）的原因。

### 10.6 CS1QA 上的高触发率是否意味着门控退化？

**对 Phi-4-mini-instruct 而言：是的，有数据支持。** 97.94%的触发率，叠加−0.73pp的门控差距（在统计上与"随机在98%样本上触发"无异），以及几乎每个样本的分类器分数都坍缩至接近0的分布，意味着分类器对该模型/数据集组合几乎不再提供任何有选择性的信息——尽管使用的是与其他场合完全相同的已训练模型和阈值，它在功能上等同于一个"全触发"开关，而非一个选择性门控。**对 Qwen2.5 在 CS1QA 上而言：同样是的**（75.42%触发率，门控差距−0.02pp——同样不具选择性，只是绝对触发率不同）。**对 Mistral 在 CS1QA 上而言：不是**——Mistral 在此数据集上的门控保留了本报告所有"模型×CS1QA"组合中最大的门控差距（+17.39pp），方向恰与退化相反（相对理想状态而言是触发不足，因为其分类器分数整体偏高而非偏低）。因此，CS1QA 是本报告中**跨模型门控行为一致性最差**的数据集，且具体的失配*方向*（过度触发 vs. 触发不足）因模型而异，并不遵循单一的共同失效模式。

### 10.7 对六条候选结论逐一核验

1. **"iMAD 对 SLM（小型语言模型）并非稳定有效" —— 得到支持。** 在**全部12个**组合中，总增量均为负（区间：−1.30% 到 −27.75%）。本报告中不存在任何一个"数据集×模型"组合，使复现的 iMAD 流程超过纯 Single-Agent 基线。
2. **"很多损失发生在自我批判阶段" —— 得到支持。** 全部12个组合中 Self-Critique Delta 均为负，且其绝对值在全部12个组合中都超过 Debate Delta 的绝对值（即自我批判始终是主要的损失来源，辩论从未是）。在可计算 SDI 的全部9个组合中，SDI 均为正，意味着自我批判阶段*自身内部*的反思相对于其*自身起点*而言是净有益的——损失反而来自于自我批判整体（包括其最初一次通过）本身就已经低于纯 Single-Agent 基线的答案质量，这很可能反映了两个基线之间真实存在的、（据第12节所述，未公开/自行重建的）不同提示词设计，而非"批判"这一步骤本身的固有属性。
3. **"辩论有时能小幅恢复，但不足以抵消早期损失" —— 得到支持。** 在12个组合中的8个上，Debate Delta 为正，但其幅度从未超过6.67个百分点（Phi/GSM8K，本表中最大的单个 Debate Delta），而与之对应的 Self-Critique Delta 却可达 −34.42pp（同样是 Phi/GSM8K）——恢复是真实存在的，但其量级持续比它试图抵消的损失小一个数量级。
4. **"classifier/gate存在跨模型或跨数据集迁移问题" —— 得到支持**，且有直接的分布证据支撑（见第10.5节）：相同的阈值与架构在完全相同的 CS1QA 数据集上，仅因模型不同就产生34%–98%的触发率区间，门控差距的选择性则从统计意义上的随机（±1pp内）到确有价值（+17.97pp）不等，具体取决于"数据集×模型"组合，没有哪个单一模型或数据集能一致地预示其表现好坏。
5. **"CS1QA上的高触发率是否意味着gate退化" —— 部分支持，取决于具体模型。** 对 Phi-4-mini-instruct 和 Qwen2.5-7B-Instruct 而言成立（二者尽管绝对触发率相差很大，分别为97.94%和75.42%，但门控差距均接近随机）；对 Mistral-7B-Instruct-v0.3 **不**成立——其 CS1QA 门控反而是涉及 CS1QA 的所有"模型×数据集"组合中选择性最强的，且触发率低得多（34.38%）。有数据支持的正确表述是：*CS1QA 的门控可靠性取决于具体模型，从确有选择性（Mistral）到功能上等同随机（Qwen2.5、Phi）不等*——而非"高触发率总是意味着退化"这样一条笼统的论断。
6. **"这些结果如何支持 MMAD-ToM 的设计动机" —— 得到支持，但范围有限，仅作为一项对比基线的发现，而非对 MMAD-ToM 自身结果的验证（后者不在本报告范围内）。** 本报告以覆盖完整设计网格的数据证明：在此处所测试的条件下，一个忠实复现的、较新的竞争性 MAD 基线（iMAD）对于中小规模开源权重学生模型而言并非一个可靠的正向干预——自我批判阶段的损失占主导，门控选择性在不同模型/数据集间不可靠，辩论带来的恢复也持续不足以抵消最初的损失。这是探索一种替代性多智能体设计（MMAD-ToM）的一项合理的、有数据支撑的动机，但本报告**并未**将 MMAD-ToM 自身的准确率与 iMAD 进行比较——如需进行该比较，应属于另一份能够获取 MMAD-ToM 自身结果的独立报告。

## 11. Parser 与可靠性审计（Parser and Reliability Audit）

### 11.1 Phi-4-mini-instruct CommonsenseQA —— 最初的38.87%辩论解析错误率

Phi-4-mini-instruct 首次完整规模的 CommonsenseQA 运行（保留在 `Baseline2 results/Phi-4-mini-instruct/CommonsenseQA/`，**仅作审计留存，非官方结果**）显示辩论角色调用错误率高达触发样本的38.87%——远高于本系列中任何其他模型/数据集组合。一次完整审计（独立于任何代码修改之前进行）确认：
- 将代码与 Qwen2.5、Mistral 完全字节/MD5一致的 `debate_engine_mcq.py` 交叉核对，排除了代码 bug 的可能性——该文件自这两个模型成功运行以来从未被修改过。
- 对≥20个原始失败样本的人工检查发现，问题模式**并非**推理缺失：几乎在每一个案例中，Phi-4-mini-instruct 的 Negative 角色*确实*在进行真实的批判性评估，但却把判断写在了自由文本 `argument` 字段中，而非填入独立的、必需的 `answer` 字段——这是一种**格式遵循失败，而非推理失败**。第二种模式：Judge 角色有时会在选项字母后附加一个右括号（例如 `"A)"` 而非 `"A"`），而 `normalize_letter` 原本的严格匹配会拒绝这种写法。
- **结论**：这既不是模型能力失败（底层判断存在且往往是正确的），也不是代码 bug（该代码在其他两个模型的成功运行中表现完全一致）——而是一种真实的、已披露的、**Phi-4-mini-instruct 特有的输出格式遵循能力不足**，在修复前的 parser 正确地将其留作未恢复的解析失败，而非悄悄猜测。

### 11.2 两项最小 parser 修复（严格按批准范围实施）

1. `normalize_letter()`：在原有去除 `.` 的基础上，增加去除结尾的 `)`，再与有效标签匹配——这是一项纯粹的格式归一化，针对 Judge 输出 `"A)"` 这类格式。
2. `recover_letter_from_argument()`：当某辩手结构化的 `answer` 字段缺失/无效，但自由文本 `argument` 字段中恰好包含**唯一**且无歧义的选项字母标记（裸字母，或 `"answer: X"`/`"(X)"` 这类模式）时，将该字母恢复作为答案。**在任何情况下都绝不**默认采用 Affirmative 的答案。**当 argument 文本中出现一个以上不同的候选字母时绝不**进行猜测——此类情形仍作为真实的、已披露的解析失败，保留原始输出。

两项修复均**仅作用于 parser 层面，只是增强了对模型已生成输出的识别能力**——未改动任何提示词文本、辩论逻辑、状态机、阈值或轮数。这是一个重要且具有实质意义的区分：本项目中任何地方都**不会**将这两项修复描述为"prompt 修复"或"方法修复"，因为它们本质上确实不是——修复前后底层模型行为与流水线逻辑在字节层面完全一致；改变的仅仅是"什么才算被成功解析出的答案"，且改变的方向仅仅是识别出模型实际上已经说出但此前未被识别的更多内容。

部署前的验证：5个新增单元测试（`TestMMLUProHardening`，是后来将同一修复扩展到 MMLU-Pro 的大写专用强化时新增的，见第11.4节）加上原有的18个，全部通过（`test_debate_engine_mcq_parser.py` 中共23个测试）；并对已交付的 CommonsenseQA_parserfix 结果中全部264个真实恢复事件重放该强化后的函数，确认0处不一致（该强化并未追溯性地改变那份已交付的报告）。

### 11.4 CS1QA 与 MMLU-Pro：schema/解析失败与多字母歧义发现

**CS1QA** 需要对同一修复理念做出 CS1QA 专属的适配：`_clean_answer()` 去除多余的包裹引号（相当于 `normalize_letter` 标点去除操作的自由文本版本），并新增 `recover_answer_from_argument()`，**仅**在 argument 中恰好出现一次明确的、自成边界的 `(answer: ...)` 标记时才恢复答案——刻意**不**尝试更宽松的文本提取（例如"答案是X"这类表述），因为自由文本不像单个选择题字母那样具有可靠的自成边界；若强行提取会有猜测答案跨度边界的风险，违反"绝不猜测"的约束。**测得的效果，作为一项真实发现披露，而非被当作修复失败**：CS1QA 的恢复率远低于 CommonsenseQA（47次恢复 / 共4864次 debate_errors = 0.97%，相比之下 CommonsenseQA 上错误减少了95.7%）。在8样本冒烟测试规模和全量规模上的人工检查均确认，这是因为 Phi-4-mini-instruct 在 CS1QA 上的失败绝大多数是自由流畅的散文式表述，仅仅是复述或表示同意，却从未使用 `(answer: ...)` 这一分隔符——该修复在这些情形下正确且保守地拒绝猜测，正如设计初衷；这并非该修复无效的证据，而是证明 CS1QA 的失败模式与 CommonsenseQA 存在本质不同（"同意但无分隔符" vs. "判断写错字段"）。

**MMLU-Pro** 除 CommonsenseQA 修复外还需要一项额外强化：原始的、大小写不敏感的字母匹配正则表达式存在误匹配 MMLU-Pro 技术性小写子项列表标记（例如某辩手自身推理中出现的"(a) 导数, (b) 积分"，在该数据集更偏技术性的表述中很常见，尤其是在最多可达10个有效选项字母A–J、碰撞风险更高的情况下）的风险。已强化为**仅匹配大写字母**。在触碰任何真实模型之前，已通过5个新增单元测试加上对已交付的全部264个 CommonsenseQA 恢复事件（见第11.2节）的完整零不一致重放来验证。**测得效果**：81.1%需要恢复的样本被成功恢复（2643/3258）；剩余6664个触发样本中的615个（9.23%，明显高于 CommonsenseQA 修复后的1.68%）经人工抽样确认属于真实的多字母歧义——argument 中提及了不止一个不同的选项字母，按照"歧义时绝不猜测"的约束被正确地留作未解决，而非修复出现回退。这是本报告中"多字母歧义"这一在任务简报中被明确提出的现象最清晰的实例：MMLU-Pro 更大的选项集合和更偏技术性的表述确实会真实提高辩论论述文本歧义的比例，而保守的 parser 正确地拒绝解决这些歧义，而非进行猜测。

### 11.6 双重花括号 JSON 模板 bug（与第11.1–11.4节的 Phi parser 恢复修复不同——这是一个真实的代码 bug，而非格式遵循能力不足）

与第11.1–11.4节（Phi 特有的输出格式遵循能力不足）不同，这是一个**真实的实现 bug**：`debate_engine_cs1qa.py` 中的 `NEGATIVE_SYSTEM`、`JUDGE_ROUND_SYSTEM`、`JUDGE_FINAL_SYSTEM` 模板使用了双重花括号（`{{...}}`），原意是供后续 `.format()` 转义使用，但实际上只有 `AFFIRMATIVE_SYSTEM` 真正经过了 `.format()` 处理——因此这三个角色实际看到的是一个字面上格式错误的 `{{"..."}}` JSON 示例，受影响的模型有时会照猫画虎地模仿这种错误格式。

- **Qwen2.5-7B-Instruct CS1QA**：在本次运行（首次尝试）中发现，错误率高达**每触发样本5.35次错误**——是本系列中此 bug 造成影响最严重的一次实例。这次有 bug 的首次尝试被完全**丢弃**（归档至 `CS1QA/_discarded_buggy_debate_run/` 并附说明性 README，从未合并进任何已报告指标），bug 被修复后，运行被干净地重做（修复后为每触发样本0.0065次错误，即第7节/第9节所报告的数字）。
- **Mistral-7B-Instruct-v0.3 CS1QA**：在该 bug 被发现之前（是在准备后续 Qwen2.5 CS1QA 运行时才发现的），**已经**使用有 bug 的代码交付完毕。影响很低——7次错误 / 635个触发样本 = 每样本0.0110次，与 Mistral 其他本就偏低的辩论错误率相当，使用的是本系列中每一次其他辩论角色调用失败所使用的同一套"重试后沿用上一轮"的兜底机制。依据本项目已确立的先例（同一类 bug 此前已在项目中更早的 `debate_engine_mcq.py`/`debate_engine.py` 中被发现并修复过一次，当时并未因此重跑已交付的低影响结果），这次 Mistral 运行**未被重跑**——其低而有界的影响已在 `run_metadata.json` 的 `post_hoc_bug_disclosure` 字段以及 `experiment_summary.md` 中原地事后披露，而非被隐藏或不加解释地悄悄略过。
- **GSM8K**（`debate_engine.py`，同一类 bug）：为保持一致性也被发现并修复，但三份已交付的 GSM8K 报告同样**未被重跑**（通过同样的低错误率信号判断其影响很低，尽管由于 GSM8K 原始产物后来才被定位到本报告开头所述的另一路径，事后已无法独立再次核实这一判断）。
- **`debate_engine_mcq.py`**（CommonsenseQA/MMLU-Pro）：**从未受到**这一具体 bug 实例的影响——它是与 `debate_engine_cs1qa.py`/`debate_engine.py` 相互独立的文件，且早在本系列中任何 CommonsenseQA/MMLU-Pro 运行开始之前，项目中就已针对这一类 bug 做过修复。

### 11.7 失败类型分类法（明确区分，避免混淆类别）

| 类别 | 示例 | 处理方式 |
|---|---|---|
| **模型能力失败**（真实的推理错误） | 任何模型给出的、已被正确解析出的答案本身就是错的 | 记为错误；根本不属于 parser 或代码问题。 |
| **格式遵循失败**（见第11.1–11.4节） | Phi 把判断写在 `argument` 而非 `answer` 中；Judge 附加了 `)`；CS1QA 散文式表述没有 `(answer: ...)` 分隔符；MMLU-Pro 中出现多字母歧义的论述 | 在目标无歧义时通过两项最小的、已披露的 parser 恢复修复处理；在存在歧义时保留为真实的、已披露的解析失败（绝不猜测）。 |
| **代码 bug**（见第11.6节） | 双重花括号 JSON 模板被原样展示给模型 | 已从源头定位根因并修复，随后要么重跑（Qwen2.5 CS1QA），要么在测得影响很低的前提下事后披露且不重跑（Mistral CS1QA、全部3份 GSM8K 报告），依据本项目已确立的"低影响事后披露"先例处理。 |

## 12. 复现局限性（Reproduction Limitations）

- **这是一次忠实的重建，而非对论文自身代码的逐字节复现。** 公开的 `Fanwei100/iMAD` 仓库仅提供 `Model.py`/`Losses.py`（分类器训练那一半）；自我批判/辩论提示词、41个特征的精确词表、以及失败处理策略均为本项目自行重建（见第2.2节），在本系列中一致使用，但未与任何非公开的原始版本核对过。
- **temperature=0.3 带来的采样方差**：每一次自我批判和辩论调用都使用非零温度；重新运行任何一个组合都不会得到字节级一致的逐样本答案，尽管本报告（见第3.1节）已表明，在一个100样本的诊断性运行上，聚合统计量对于重新处理/并发数变化是稳定的。
- **CS1QA 使用的是1847条子集，而非官方全量9237条**，本系列全程如此（见第5.3节)——若与使用完整数据集的另一次 CS1QA 复现相比较，二者并不直接可比。
- **CS1QA 的正确性依赖于裁判**：一个外部的 Qwen/Qwen3.5-9B 裁判以 temperature=0.0 对每一个 CS1QA 答案评分；虽然 temperature=0.0 能最大程度降低（但无法完全消除）裁判侧的采样方差，但该裁判本身是一个独立的模型，有其自身的失效模式，本报告中 CS1QA 的准确率数字会继承该裁判存在的任何系统性偏差，这是 GSM8K/CommonsenseQA/MMLU-Pro 的精确匹配评分所不具有的。
- **全部12个 Single-Agent 基线均为复用，未重新运行**（见第5.5节）——均来自一次单独完成的 `Single-AgentV2/` 评测，每个数据集使用其自身的提示词设计（GSM8K/CommonsenseQA/CS1QA/MMLU-Pro 均为4字段结构化 CoT+Reflection 提示词，与自我批判流水线自身的提示词不同）。因此 Self-Critique Delta 衡量的是"自我批判流水线*第一遍*的答案"相对于"*使用不同提示词*的纯基线"的差异，而非相对于"自我批判提示词本身的单遍版本"的差异——SDI（见第6节）是本报告为分离出后一个更窄的问题而做出的尝试，但它与 Self-Critique Delta 是不同的量，二者不应被混为一谈。
- **无法恢复的解析失败在每个组合中都非零但很小**（见第7节最右列，最大值为 Mistral/MMLU-Pro 的1.61%）——这些样本按"永不排除"策略（见第2.2节）被记为错误，这会使每一个 Acc(0)/最终准确率数字相对于一个假设性的"直接排除这些样本"的策略而言略微被压低。
- **流水线自身各阶段之间不同的提示词/schema 设计本身可能对较弱的模型产生不成比例的影响**——自我批判提示词那套结构化的8字段 JSON 输出 schema，对 Mistral（GSM8K 上 schema 有效率仅65.3%）和 Phi（76.8%）而言，明显比对 Qwen2.5（99.1%）更难遵循，本报告无法完全区分"自我批判推理这一步骤本身把答案改坏了"与"更复杂的输出 schema 本身独立于批判内容而降低了答案质量"这两种可能性，对这两个较弱的模型尤其如此。
- **Judge 提前终止规范存在的缺口**（见第2.2节）意味着当辩论双方从第1轮起就已一致时，辩论有时会无谓地跑满5轮——这会增加 token 开销，但不一定会影响第10节所分析的转移计数；为保证全部12个组合彼此可比，该行为在所有组合中原样保留未修复，代价是未能体现论文设计初衷所能达到的最具 token 效率的实现方式。

## 13. 最终发现（Final Findings）

### 13.1 可以确信的结论

- 在设计完整的3模型×4数据集网格上，**复现的 iMAD 流程在所测试的12个组合中没有一个超过纯 Single-Agent 基线**（见第7节、第10.7节第1条）。
- **在每一个组合中，自我批判阶段而非辩论阶段是这一差距的主要来源**（见第10.7节第2条）——Self-Critique Delta 的绝对值在12/12个组合中都超过 Debate Delta 的绝对值。
- **选择性辩论在多数组合（12个中的8个）上是净有益的**（见第10.3节），其幅度虽小但真实存在（最高可达+6.67pp）——它是一种真实的、尽管有限的纠错机制，而非统计噪声（已通过每个组合精确的 DR/RR/转移计数 sanity check 通过来验证）。
- **复用的、固定的分类器门控（τ=0.7，按模型分别在 PubMedQA 上训练）表现出真实但不一致的选择性**——从确有价值（Mistral/GSM8K，门控差距+15.96pp）到统计意义上与随机无异（Qwen2.5/CS1QA、Qwen2.5/CommonsenseQA、Phi/CS1QA）不等——且没有任何单一模型或数据集能够预示某个具体组合会落入哪种情形（见第10.5–10.6节）。

### 13.2 应保持谨慎、范围更窄的结论

- 自我批判阶段损失的具体*幅度*，与本报告为 Single-Agent 基线所做的提示词设计选择（一次结构不同、提示词也不同的评测，见第12节）纠缠在一起——其定性方向（自我批判表现不如一次性作答）已由 SDI 在每一个可计算的组合中均为正值这一事实得到充分支持（自我批判的*内部*反思相对于其*自身*起点是有帮助的），但 Self-Critique Delta 的具体百分点大小应被理解为"自我批判表现不如本项目特定设计的 Single-Agent 基线"，而不应被理解为自我批判这一技术本身、与提示词设计无关的固有属性。
- CS1QA 门控行为因模型而异这一发现（见第10.6节）基于每个模型在一个数据集上各一个数据点（共3个数据点）；这在本数据中是一个真实、已验证的模式，但若要推广为"门控在自由文本任务上总是如此因模型而异"，还需要测试本网格未覆盖的更多自由文本数据集。
- 第2.2节所述自行重建的41个特征及其词表未与论文原始版本核对过；不能排除一套不同的重建方案会产生一个实质上不同、校准更好的分类器——本报告只能就实际使用的这一具体重建方案发表意见。

### 13.3 对 MMAD-ToM 下一步实验的直接启示

1. 未来任何将 MMAD-ToM 与 iMAD 进行比较的研究，都应**分别**报告 Self-Critique Delta 和 Debate Delta（而不仅仅是 Total Delta），因为本报告表明二者可能朝相反方向变化，仅比较 Total Delta 会掩盖 MMAD-ToM 自身优势（如果存在）的真正来源。
2. 若 MMAD-ToM 采用类似的选择性门控设计，本报告关于门控退化的发现（见第10.5–10.6节）表明，值得作为后续消融实验测试"阈值重新校准"或"按模型/按数据集在验证集上重新选择阈值"这一步骤，因为此处 τ=0.7 从未被重新选择过，而其表现却千差万别。
3. GSM8K 的结果（在全部3个模型上都是所有数据集中损失最大的）表明，开放式数值推理可能是任何 MMAD-ToM 与 iMAD 正面对比中特别有价值的一个任务类型，因为它在所有测试数据集中最清晰、最显著地区分开了自我批判阶段的损失与辩论阶段的恢复。

### 13.4 论文中应当——以及不应当——如何表述

**恰当的表述方式**："我们在3个模型骨干、4个数据集（共12个组合）上忠实复现了 iMAD 作为 Baseline 2。复现的流程在所测试的任何组合上均未超过纯单智能体基线；损失集中在自我批判阶段，选择性辩论在多数情形下带来了小幅、真实但不足以弥补损失的恢复。分类器门控的选择性在不同模型和数据集间存在显著且不一致的差异。"

**应避免的表述方式**：**不应**无条件地声称本报告表明"iMAD 不起作用"或"我们的复现失败了"——本报告重建了论文未公开的若干组件（见第2.2节），使用的是设计不同的提示词所产生的 Single-Agent 基线进行对比（见第12节），且仅覆盖了7B/mini能力档位的3个模型骨干在4个特定数据集上的表现。更站得住脚、也更有价值的结论是范围更窄的：*对于本报告所披露的这一具体重建方案，在这些具体的模型和数据集上，此处所实现的 iMAD 并未超过纯单智能体基线*——这恰恰是促使我们探索 MMAD-ToM 作为替代方案的发现，而不是"选择性多智能体辩论"作为一整类方法本身不可行的论断。
