# MMAD-ToM 提示词架构与使用说明

## 1. 目的

本文说明修订后的 MMAD-ToM 设计中，七个提示词模板如何协同工作。三名学生智能体（M、P、Q）在 Phase 0 独立作答，随后进行四轮同步辩论。Round 1 和 Round 3 侧重同伴层面的心智理论（ToM）分析。在 Round 2 和 Round 4 开始前，教师分别诊断每名学生，并为其提供当轮专属指导。每轮辩论都会展示同伴报告的置信度，以研究置信度与答案修改之间的关系。

**设计与现有代码：** 本文描述的是目标设计。此前的 Python 脚本在 Round 2 和 Round 4 *结束后*调用教师；必须调整调用顺序，才能实现本文流程。

## 2. 提示词文件与职责

| 模板 | 发送对象 | 用途 |
| --- | --- | --- |
| Phase 0 学生系统提示词 | Phase 0 的 M、P、Q | 规定独立推理和 JSON 输出；不提供历史答案、同伴信息或教师指导。 |
| Phase 0 用户提示词 | Phase 0 的 M、P、Q | 提供当前题目及题目 ID。 |
| 辩论轮学生系统提示词 | Round 1–4 的 M、P、Q | 规定如何比较自身与同伴的推理、单独看待置信度，以及报告答案修改情况。 |
| 同伴轮用户提示词 | Round 1、3 的 M、P、Q | 提供题目和上一阶段的学生状态，不包含教师指导。 |
| 教师系统提示词 | Round 2、4 开始前的教师 | 规定每次只诊断一名学生，处理不确定性，并给出不直接泄露答案的指导。 |
| 教师用户提示词 | Round 2、4 开始前的教师 | 提供题目、目标学生的历史、其实际看到的同伴信息，以及此前收到的教师指导。 |
| 教师轮用户提示词 | Round 2、4 的 M、P、Q | 提供上一阶段的学生状态，以及刚为目标学生生成的专属指导。 |

“教师用户提示词”发送给**教师**，用于生成指导；“教师轮用户提示词”在指导生成后发送给**学生**。仓库中的 Markdown 文件只是模板：实验脚本需要读取模板、替换变量，再将完整文本传给相应模型。

## 3. 单题执行顺序

| 阶段 | 调用顺序 | 可用历史 |
| --- | --- | --- |
| Phase 0 | M、P、Q 独立作答；三人完成后统一记录初始输出。 | 仅题目 |
| Round 1 | 根据 Phase 0 的完整状态构造提示词；三人完成后统一追加输出。 | Phase 0 |
| Round 2 开始前 | 教师分别诊断 M、P、Q，每名学生调用一次。 | 截至 Round 1 |
| Round 2 | 每名学生读取 Round 1 的状态和**自己的**新指导；三人完成后统一追加输出。 | Round 1 及当轮指导 |
| Round 3 | 根据 Round 2 的状态构造同伴提示词；不再次注入 Round 2 的指导。 | Round 2 |
| Round 4 开始前 | 教师再次分别诊断 M、P、Q。 | 截至 Round 3，包含此前的指导记录 |
| Round 4 | 每名学生读取 Round 3 的状态和**自己的新指导**；三人完成后统一追加最终输出。 | Round 3 及当轮指导 |

每名学生始终读取**上一阶段的统一快照**。程序可以依次调用 M、P、Q，但必须先将当轮结果保存在 `round_outputs` 中，等三人全部完成后再写入历史。每道题共需 15 次学生调用和 6 次教师调用，不包括独立的评估调用。

## 4. 输入、输出与路由

### 学生调用

将匹配的系统提示词和用户提示词发送给**同一名学生模型**。辩论轮的用户模板应包含题目、该学生紧邻上一阶段的答案、推理和置信度，以及另外两名学生在同一阶段的对应信息。教师轮还需加入且只加入该学生自己的当轮指导。

解析 `question_id`、`predicted_output`、`reasoning`、`confidence`（0–100 的整数）和 `revised`（布尔值）。程序应比较当前答案与紧邻上一阶段的规范化答案，核实 `revised` 的值，并单独记录解析失败。

### 教师调用

每次教师调用只诊断**一名目标学生**，不能一次合并诊断三人。教师输入包括题目、当前偶数轮开始前目标学生的历史、该学生在此前作答前实际看到的同伴内容，以及此前收到的教师指导。不得提供标准答案。

解析并保存 `INDEPENDENT_ANSWER`、`INDEPENDENT_REASONING`、`QUESTION_INTENT`、`MISCONCEPTION_HYPOTHESIS`、`AGENT_UNDERSTANDING` 和 `GUIDANCE`。将后三项组成独立的 Tutor Guidance 区块，在**当前 Round 2 或 Round 4**发送给目标学生。保存完整的原始教师输出和解析结果，以供核查；不得将其他学生的诊断发送给目标学生。

**解释边界：** 教师的“独立答案”只是暂定判断。如果题目和学生历史出现在同一次模型调用中，仅凭输出顺序无法保证教师的答案未受学生回答影响。“置信度驱动的顺从”也只是诊断假设：学生看到高置信度同伴后改答，并不能单独证明置信度造成了这次改答。

## 5. 模板变量

| 变量 | 含义 |
| --- | --- |
| `{task_type_guidance}`、`{answer_format}` | 数据集对应的任务说明和最终答案格式。 |
| `{question_block}` | 题目 ID、题干，以及适用时的选项或代码。 |
| `{round_num}` | 当前辩论轮次，取值为 1–4。 |
| `{own_previous_answer}`、`{own_previous_reasoning}`、`{own_previous_confidence}` | 目标学生紧邻上一阶段的状态。 |
| `{peer_1_*}`、`{peer_2_*}` | 另外两名学生上一阶段的标签、模型名称、答案、推理和置信度。 |
| `{target_label}` | 本次教师调用要诊断的学生标签。 |
| `{target_student_history_through_previous_round}` | 准备 Round 2 时截至 Round 1 的目标学生历史；准备 Round 4 时截至 Round 3 的历史。 |
| `{peer_exposure_history_for_target}` | 各已完成轮次中，目标学生作答前实际看到的同伴信息。 |
| `{prior_tutor_guidance_or_none}` | 准备 Round 4 时填入 Round 2 的指导；其他情况填“无”。 |
| `{teacher_guidance_for_this_agent}` | 当前教师轮刚为目标学生生成的指导。 |

**实现提示：** 如果使用 Python 的 `str.format()`，系统提示词中 JSON 示例的字面花括号必须写为 `{{` 和 `}}`；也可以使用能够区分字面花括号与模板变量的渲染方法。

## 6. 生成与评估

学生和教师调用的目标生成参数均为 `temperature=0.3`、`top_p=0.9`、`max_tokens=2048`。旧脚本默认使用 `temperature=0.7`，正式运行前应核对实际生效的配置。

每道题应保存每名学生的五条输出（Phase 0 加四轮）、六条教师输出，以及准确输入或足以重建信息接触过程的记录，以便核查答案变化。评估 judge 独立于辩论流程，不能将标准答案或正确性判断反馈给智能体。CS1QA 需要先接入对应的正确性 judge，才能计算该数据集的 drift 和 recovery。
